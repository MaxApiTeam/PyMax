PyMax 2.4.1
===========

Версия 2.4.1 добавляет управляемую версию mobile runtime, одноразовое
подключение, отложенные сообщения, непостоянные сессии, обновление фотографии
группы и новые лимиты для upload и 2FA. Также расширены модели входящих сообщений
и исправлена отправка голосовых сообщений и кружков.

Ниже перечислены пользовательские изменения относительно ``2.4.0``.

Новый публичный API
-------------------

* ``Client`` принимает ``app_version`` и ``VersionCatalog``. Встроенный
  каталог содержит fingerprints до ``26.28.0``, рекомендуемая версия по
  умолчанию - ``26.25.0``. ``VersionCatalog(remote=True)`` дополняет встроенные
  данные с ``hashes.pymax.org``; неизвестная версия вызывает
  ``VersionNotFoundError`` при запуске клиента.
* ``connect()`` выполняет один login-цикл, вызывает ``on_start`` и возвращает
  управление с открытым соединением без reconnect loop. Состояние запущенного
  соединения доступно через ``is_connected``.
* ``send_message()``, ``Message.answer()`` и ``Message.reply()`` принимают
  ``send_at`` как ``datetime``, ``timedelta`` или Unix time в секундах.
  ``None`` и ``0`` означают немедленную отправку; входящие сообщения содержат
  необязательное ``delayed_attributes``. Соответствующий ``DateTimeUnion``
  экспортируется из ``pymax.api.messages``.
* ``change_group_profile()`` принимает необязательный ``Photo`` и автоматически
  загружает его перед обновлением группы. ``name`` также стал необязательным;
  поля со значением ``None`` не отправляются.
* ``ExtraConfig.upload_timeout`` задает общий timeout HTTP-загрузки ``File``,
  ``Video``, ``Voice`` и ``VideoNote``; значение по умолчанию - 900 секунд,
  а неположительное значение отключает общий timeout.
* ``ExtraConfig.password_max_attempts`` ограничивает попытки ввода пароля 2FA.
  ``None`` означает отсутствие лимита, а исчерпание попыток вызывает
  экспортируемый ``PasswordAttemptsExceededError``.
* ``ExtraConfig.relogin`` позволяет отключить автоматический сброс сессии и
  повторную авторизацию после отзыва login token; по умолчанию поведение
  включено.
* ``ExtraConfig.persist_session=False`` выбирает экспортируемый
  ``InMemoryStore`` вместо SQLite или пользовательского ``store``. Такая сессия
  теряется при пересоздании runtime, поэтому reconnect без заданного token снова
  запускает авторизацию.
* ``Message.link`` содержит ``ReplyLink`` или ``ForwardLink`` с исходным
  сообщением и чатом; forward также может содержать имя, ссылку, тип доступа и
  иконку исходного чата.
* ``CallAttachment`` получил ``call_type`` и ``hangup_type``, а
  ``ControlAttachment`` - необязательный ``title``.

Изменения поведения
-------------------

* Конфигурация и fingerprint ``Client`` теперь подготавливаются при
  ``connect()``/``start()``. Выбранная версия определяет согласованные
  app version, build number и fingerprint; подготовленная конфигурация и
  сгенерированный device ID сохраняются между reconnect.
* TCP-клиент по умолчанию использует ``api2.oneme.ru`` и добавляет сертификат
  Max в стандартный trust store как для прямого, так и для proxy TLS.
  User-agent ``WebClient`` обновлен до web-версии ``26.8.4``.
* Автоматически создаваемые ``device_id`` и ``mt_instance_id`` теперь являются
  строками из 16 шестнадцатеричных символов. Значения из существующей сессии
  продолжают использоваться без замены.
* Сгенерированный device/user-agent теперь сохраняется в сессии и
  восстанавливается до handshake. Характеристики устройства остаются
  стабильными, но app version и build number берутся из текущей конфигурации;
  явный ``ExtraConfig.user_agent`` имеет приоритет. Старые SQLite-сессии
  мигрируют автоматически.
  Пользовательским store рекомендуется сохранять новое необязательное поле
  ``SessionInfo.user_agent``; значение ``None`` остается совместимым.
* ``Voice`` получил аргумент ``duration`` в миллисекундах. При ``None`` классы
  ``Voice`` и ``VideoNote`` определяют длительность через необязательный extra
  ``video``.
* ``File.size()``, ``Video.size()``, ``Voice.size()`` и ``VideoNote.size()``
  теперь следуют redirect при HEAD-запросе к URL-источнику.

Исправления
-----------

* Исправлены wire payload голосовых сообщений и кружков: длительность,
  waveform и thumbhash передаются в ожидаемом Max формате.
* Если отправка или редактирование с ``Voice``/``VideoNote`` получает
  ``attachment.not.ready``, PyMax ждет событие готовности до 60 секунд и
  повторяет запрос один раз.
* ``VideoAttachment.preview_data`` теперь необязателен, поэтому входящее видео
  без preview больше не вызывает ошибку валидации.
* ``ContactAttachment`` принимает payload без ``contact_id`` и возвращает для
  этого поля ``None``.
* Консольный provider email-кода 2FA больше не блокирует asyncio event loop во
  время ``input()``.

Breaking changes и migration notes
------------------------------------

* ``add_reaction()``, ``get_reactions()`` и ``remove_reaction()`` теперь
  принимают ID сообщений как ``int`` вместо ``str``. Ключи результата
  ``get_reactions()`` остаются строками, как в ответе Max.
* ``ExtraConfig.generate_user_agent()`` теперь требует согласованные
  ``app_version`` и ``build_number``. Коду, который вызывал метод напрямую,
  нужно передать оба значения.
* ``VideoNote`` больше не является подклассом ``Video``. Если код использовал
  ``isinstance(value, Video)``, проверяйте ``(Video, VideoNote)`` явно.
* Отправка ``Voice`` без ``duration`` теперь требует extra ``video`` для
  автоматического определения длительности. Без extra передавайте длительность
  в миллисекундах вручную.
